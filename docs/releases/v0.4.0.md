# v0.4.0

## Summary

- Aligns README and workflow templates with the first release tag that includes `codex-review-ready`.
- Makes `v0.4.0` the recommended consumer pin for the current repo-governance toolchain.

## Included highlights

- PR Intake Gate includes the current marker fail-fast behavior for unsafe empty `bot_comment.marker` values.
- Codex Review Gate includes bounded resolution waiting and current review handling from the current mainline.
- Codex Review Ready is included as a separate commit-status reconciler action.
- Workflow templates point consumers at `@v0.4.0` instead of `@v0.3.0`.
- Template and repository governance validation catches empty action refs, unresolved workflow placeholders, missing `persist-credentials: false` in checked-in `pull_request_target` workflows, and empty bot comment markers.

## Migration

- Update action refs from `@v0.3.0` to `@v0.4.0`.
- Require `pr-intake-gate` in repositories that use the bundled PR intake workflow.
- Require `codex-review-ready` where the repository uses Codex Review completion as a pre-merge barrier.
- For mature or high-risk repositories, optionally replace `@v0.4.0` with the full commit SHA resolved from the `v0.4.0` tag after release.

## Notes

- `v0.3.0` does not contain `actions/codex-review-ready`; do not treat it as a valid pin for the Codex Review Ready workflow.
- `v0.2.0` and `v0.3.0` may remain tag-only unless separate GitHub Releases are intentionally created.
- This release does not include strict schema validation, license selection, code of conduct work, or consumer repository rollout.

## Post-merge release commands

Run these commands only after this PR is merged. The `v0.4.0` tag should point to the merged commit that contains the `@v0.4.0` README and template references. If the local `main` branch is divergent, use a clean checkout or otherwise resolve that local state before running the commands; do not reset unrelated local work.

```bash
git fetch origin main --tags
git switch main
git pull --ff-only origin main
git tag -a v0.4.0 -m "v0.4.0"
git push origin v0.4.0
gh release create v0.4.0 \
  --title "v0.4.0" \
  --notes-file docs/releases/v0.4.0.md
```

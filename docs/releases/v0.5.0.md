# v0.5.0

## Summary

- Adds strict root-level PR Intake policy validation.
- Unknown top-level policy keys now fail fast instead of being silently ignored.
- Catches typos such as `highrisk_path_globs` before they can weaken local governance policy.

## Highlights

- The PR Intake policy JSON schema now sets root-level `additionalProperties` to `false`.
- The PR Intake Gate runtime rejects unknown top-level policy keys and prints the allowed key list.
- `scripts/validate_repo_governance.py` catches unknown root keys in checked-in policies, templates, and examples.
- Tests cover typo and unrelated unknown keys.
- Policy and rollout docs describe the fail-fast behavior.

## Migration

- Validate each local `.github/pr-intake-gate.yml` before upgrading the action ref.
- Remove or fix unknown top-level keys. For example, use `high_risk_path_globs`, not `highrisk_path_globs`.
- Keep metadata keys only when they are explicitly supported by both schema and runtime; `llm` remains allowed as an existing extension key.
- Update action refs from `@v0.4.0` to `@v0.5.0`, or pin to the full `v0.5.0` commit SHA after the release tag is created.

## Compatibility

- The checked-in repo-governance policy, starter template, and example policies validate with strict root-level keys.
- Known local consumer policies were read-only checked during PR #24 and were compatible.

## Notes

- `v0.4.0` remains unchanged and must not be retagged.
- Consumer rollout is a separate step after `v0.5.0` exists.

## Post-Merge Release Commands

Run these commands only after this PR is merged. The `v0.5.0` tag should point to the merged commit that contains the `@v0.5.0` README and template references. Do not move `v0.4.0`.

```bash
git fetch origin main --tags
git switch main
git pull --ff-only origin main
git tag -a v0.5.0 -m "v0.5.0"
git push origin v0.5.0
gh release create v0.5.0 \
  --title "v0.5.0" \
  --notes-file docs/releases/v0.5.0.md
```
